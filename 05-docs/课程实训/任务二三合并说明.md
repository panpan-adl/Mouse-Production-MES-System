## 2. 同步与隐私边界

- 身份只取现有登录会话；所有原件、向量、图谱、事件均按owner隔离。客户端不能通过传入owner读取别人的资料。
- `version` 是最新操作版本，`activeVersion` 是当前可检索版本。失败替换时可出现 `version=2, activeVersion=1`；重试使用原版本。
- `RagGraphBridge` 将图谱发布加入文件发布的同一个MySQL事务。Neo4j先写入不可变build，MySQL只在双方成功后切换可见版本；失败build不会进入授权检索。这里没有宣称跨MySQL与Neo4j的分布式事务，未被采用的图构建可能留存到后续版本化清理。
- 删除先共同提交文件与图谱的不可检索状态，再清理原件及图数据库。清理失败记录为 `CLEANUP_PENDING`，刷新后仍可从处理记录重试。
- 文件库管理的编号禁止通过纯图谱接口单独修改、删除，避免两边版本分离。旧的纯文本导入继续兼容。
- 向量适配器只接受任务三已经授权的Chunk对象，返回同一对象及真实build片段编号。精确文本、模型、用户和活动版本匹配时复用任务二上传时生成的向量，避免同一片段重复调用嵌入模型；查询问题仍需生成向量。
- 向量保存在本机MySQL JSON列，通过余弦精确检索召回，默认阈值0.5。这是课程规模的持久化向量检索，没有部署专用大规模ANN向量数据库。

## 3. 统一启动与模型配置

在本机项目根目录双击 `启动知识图谱.cmd`，输入本机API Key，保留启动窗口。统一前端为 `http://127.0.0.1:5173/knowledge`，后端8080。沿用已有MySQL、Redis及本机Neo4j启动流程；不会重新初始化原业务数据库。

| 用途 | 默认配置 |
| --- | --- |
| 图谱抽取、问答模型 | `MES_KNOWLEDGE_MODEL=doubao-seed-2-1-lite-260915` |
| 模型地址 | `MES_KNOWLEDGE_MODEL_BASE_URL=https://ark.cn-beijing.volces.com/api/v3` |
| 图谱、问答密钥 | `MES_KNOWLEDGE_MODEL_API_KEY`，启动时隐藏输入，仅当前进程环境 |
| 文本嵌入模型 | `MES_EMBED_MODEL=doubao-embedding-vision-251215`，1024维 |
| 嵌入地址、密钥 | `MES_EMBED_BASE_URL`、`MES_EMBED_API_KEY`；启动脚本默认复用知识模型配置，可在启动前单独指定 |
| 原件存储 | `MES_RAG_STORAGE`，脚本默认项目 `.runtime/rag-files` |
| 向量阈值 | `MES_RAG_MIN_SCORE=0.5` |

同一个API Key有聊天模型权限，不代表已经开通嵌入模型权限。页面“配置已填写”也不等于真实调用成功：上传文件后必须看到文件和图谱均为“已发布”。如果返回HTTP403／404，需要检查火山方舟对应模型的开通状态、模型ID和API权限。密钥不应提交GitHub或粘贴到对接文档。

原件、解析结果和向量存本机，但需要把片段和问题发送至配置的模型服务，属于本地资料库＋远程模型方案。任务二的调用次数限制不覆盖任务三的图谱抽取与问答调用，也不等于人民币预算硬限制。合并启动脚本不设置业务助手的 `MES_AI_MODE=remote`。

## 4. 接口兼容

- 原件管理继续使用 `/api/rag/documents`、`/events`、`/retry`、`/download`；成功响应增加 `graphStatus`，删除响应包括两个清理状态。
- 图谱、状态与问答继续使用 `/api/knowledge/*`。状态 `revision=task2-task3-r1`，`vectorRetrieverConnected=true` 表示已装配向量检索器。
- `/api/rag/messages` 也可以转发三种模式，接收 `question`、`mode`、可选 `documentIds`，共用任务三的引用与版本校验。
- `/api/rag/status` 的 `graphAvailable=true` 表示已装配图谱桥，`embeddingConfigured` 只判断配置非空，不主动消耗模型调用。
- 原同步payload接口仍保留兼容，但统一页面已经自动同步，不需要再手工重复发布。
- 处理记录增加持久化 `rag_graph_sync`，记录每个owner、文件、版本的图谱状态。现有任务二READY资料可通过重试补齐图谱。
