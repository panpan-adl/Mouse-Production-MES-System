# MouseMES 任务三部署与验收说明

任务三在原MES中增加个人私有知识图谱工作台，入口为 `/knowledge`，位于“智能与提醒”菜单。文本导入后调用大模型提取实体关系，写入Neo4j；问答时检索实体关联的两跳子图，将关系和原文交给模型生成带来源的回答。

## 一 功能与老师要求对应

| 老师要求 | 当前实现 |
| --- | --- |
| 隐私库文件转图数据库并更新 | 支持PDF／DOCX／TXT／MD／CSV原件及文本导入；按用户隔离，模型抽取后写入Neo4j，版本更新和删除接口已实现 |
| RAG与GraphRAG选择或融合 | 三种模式：RAG、GRAPHRAG、HYBRID；RAG已接入真实1024维嵌入向量及MySQL余弦召回 |
| 前端嵌入图谱可视化 | SVG实体节点、曲线关系、实体查询、资料范围、缩放、回答子图高亮、文件页码／段落及图谱JSON导出 |
| GraphRAG智能对话 | 根据实体名称匹配种子并扩展两跳，跨文件连接同名实体，提供原文片段和版本来源；需要真实模型配置 |

这里采用的是实体关系图谱增强检索，不包含社区发现、社区摘要或全局社区搜索，不宣称实现微软GraphRAG的完整索引流水线。

本机推荐先填写 `08-environment/knowledge.local.json`，再双击根目录 `启动知识图谱.cmd` 自动加载模型和Neo4j配置。密钥文件已排除Git，不能打包给同学。以下通用配置供其他环境部署参考；最新联合验收见《任务三五项完善与扩展验收.md》。

## 二 所需环境

原项目仍需要Java17、Maven、Node.js、MySQL和Redis。新增图数据库为Neo4j 5.26 LTS Community，使用Query API `/db/{database}/query/v2`，不使用旧版事务HTTP接口。模型服务需支持 `POST /chat/completions`、messages参数，以及 `choices[0].message.content`、`finish_reason` 返回格式。

模块默认关闭。启用后新增 `mm_kg_document` 及任务二的 `rag_*` 独立表，不重建原业务表；建表SQL为 `01-backend/src/main/resources/sql/knowledge_graph.sql`。建议先使用隔离演示数据库验证，再决定正式课程演示所用的数据库。

## 三 启用Neo4j

已有Neo4j Desktop时创建5.26实例，设置密码并启动HTTP端口7474。默认数据库为neo4j。Neo4j数据与MySQL业务数据分开存储。

也可使用已提供的Docker Compose文件。在PowerShell中设置密码后启动：

```powershell
$env:MES_KNOWLEDGE_NEO4J_PASSWORD = '替换为你设置的Neo4j密码'
docker compose -f 08-environment/compose.knowledge.yml up -d
```

Compose只将7474和7687绑定到本机。图数据保存在独立命名卷。停止时使用同一文件执行 `docker compose ... stop`；正常停止不删除数据卷。密码首次创建后保存在Neo4j数据目录，修改环境变量不能自动更改已有实例密码。

## 四 配置并启动后端

本项目已确定使用火山方舟的 `doubao-seed-2-1-lite-260915`，可直接按[火山方舟接入说明](火山方舟接入说明.md)运行配置脚本，避免手动填写模型地址。下列通用环境变量方式仍可用于其他兼容服务。

在启动项目的同一个PowerShell会话中配置以下变量。例子中的地址、模型名和密码需要替换，不能原样作为有效配置。

```powershell
$env:MES_KNOWLEDGE_ENABLED = 'true'
$env:MES_KNOWLEDGE_NEO4J_URL = 'http://127.0.0.1:7474'
$env:MES_KNOWLEDGE_NEO4J_DATABASE = 'neo4j'
$env:MES_KNOWLEDGE_NEO4J_USER = 'neo4j'
$env:MES_KNOWLEDGE_NEO4J_PASSWORD = '替换为你的Neo4j密码'
$env:MES_KNOWLEDGE_MODEL_BASE_URL = 'https://你的模型服务地址/v1'
$env:MES_KNOWLEDGE_MODEL = '你的模型名称'
$env:MES_KNOWLEDGE_MODEL_API_KEY = '你的模型密钥'
./08-environment/Start-MouseMES.ps1
```

`MODEL_BASE_URL`不含 `/chat/completions`，后端会自动追加。模型必须能输出关系JSON和带引用的自然语言回答。模型接口密钥与Neo4j密码仅在后端环境中配置，不放入前端源码或Git提交。本地兼容服务如果不需要认证，可以填写该服务允许的非空占位值。

启动脚本会构建新后端包；若8080已由旧服务占用，需要先正常停止原项目再启动，以加载新的环境变量。不要使用 `SkipBuild` 跳过首次构建。前端默认地址为 `http://127.0.0.1:5173/knowledge`，以实际启动日志为准。已有四档演示端口使用不同启动脚本，不能把此处5173与原5175演示库混用。

进入页面点击“检测连接”，确认Neo4j显示“已连接”。模型名称显示只表示必要字段非空；点击“测试模型”实际调用模型并检查简短指令响应，状态显示“已实测连接”。该测试会产生一次模型请求，随后仍需通过导入与问答核对抽取和回答质量。配置缺失或连接失败时页面会明确报错，不会生成模拟节点或模拟答案。

## 五 演示顺序

1. 使用用户A登录，进入“私有知识图谱”。
2. 导入 `演示资料/A100生产工艺.md` 和 `演示资料/点胶机点检要求.md`。资料明确标注为课程演示示例，不代表实际MES订单。
3. 查看点胶工序、点胶机、设备管理员等节点及关系，点击节点展示关系原文。
4. 选择GraphRAG提问“点胶工序使用的设备由谁负责？”，核对两个文件之间经点胶机连接的两跳关系。模型抽取质量会影响具体关系，请核对实际结果，不填写预设验收数字。
5. 选择RAG及融合模式比较返回来源，说明当前RAG是否已接入任务二向量检索。
6. 更新点检资料，递增版本；核对回答来源版本变为新版本。删除一份资料后核对对应关系退出检索。
7. 换用户B登录，确认不能查看A的文件或通过问答获取A的资料。

## 六 数据一致性与范围

图实体按用户隔离，同一用户的相同实体名称可跨文件连接。关系带owner、documentId、version、buildId、chunkId和原文引用。MySQL保存当前可见buildId和分块文本，Neo4j先成功写图，随后MySQL发布有效版本；查询严格限定本用户和已发布构建。

每个文件最多12000字符，1800字符分块并重叠150字符。抽取逐片进行，每片最多30条关系；问答最多12个来源片段、40条关系。可视化最多150条关系，超过时显示截断提示。实体名称匹配不足时由模型在当前授权图的最多300个候选中定位同义称呼，仍可能对歧义称呼拒绝猜测；使用明确的实体名称更可靠。

模型返回的实体和引用须在输入原文中找到，回答须引用有效来源编号。程序不会执行文件或模型生成的Cypher/SQL。引用校验不能替代人工检查语义正确性，答辩时应展开来源核对。当前每次提问独立检索，不提供多轮指代消解或持久化聊天历史。

删除先提交不可检索状态DELETED_PENDING，再清理物理关系；若Neo4j离线则返回cleanupPending并可按同版本重试。待清理记录保存在MySQL中，刷新或重新登录仍能恢复；清理成功后状态变为DELETED。旧构建及崩溃遗留构建不参与检索，尚未提供定时回收。文件库和向量索引现已通过RagGraphBridge自动共同发布与撤销，失败可重试；rag_progress持久化处理阶段，页面刷新后继续查看。
