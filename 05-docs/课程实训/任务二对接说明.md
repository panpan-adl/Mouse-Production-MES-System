# MouseMES 任务二与任务三对接说明

本文件供负责任务二 RAG 的同学使用。任务三已增加独立知识库模块，双方共用登录用户身份和文件版本约定。任务二负责私有文件库、多格式解析和向量检索；任务三负责实体关系提取、Neo4j图谱、图谱展示及GraphRAG问答。先遵守以下接口实现，再进行分支合并。

## 一 分工和代码位置

| 范围 | 任务二负责 | 任务三已提供 |
| --- | --- | --- |
| 身份 | 复用登录会话，不能另造用户编号 | 从服务端 `userInfo.id` 取得 owner |
| 文件库 | 原始文件上传、下载、更新、删除，用户隔离；多格式解析 | 文本和Markdown内容导入；作为独立联调入口 |
| 文本 | 提取PDF、DOCX等正文，保留页码等原文定位 | 接收解析后的Unicode文本，分块及版本控制 |
| 索引 | 嵌入模型、向量库、向量索引更新删除 | Neo4j实体、关系、两跳检索、来源引用 |
| 问答 | 实现 `RagRetriever`，接入真正的向量召回 | RAG、GRAPHRAG、HYBRID三种模式及问答页面 |

后端新增代码位于 `01-backend/src/main/java/com/mouse/mes/knowledge/`。前端入口为 `/knowledge`，菜单“智能与提醒 → 私有知识图谱”。页面文件为 `02-frontend-web/src/views/knowledge/KnowledgeWorkspace.vue`。原MES业务智能体 `/assistant` 继续处理实时业务查询。

## 二 文件身份和版本约定

- `documentId` 是同一逻辑文件的稳定编号，1到64位ASCII字母、数字、下划线或短横线，建议UUID；更新时保持编号。
- `version` 是正整数，文件创建、更新和删除时递增。重试必须重用同一版本，不能每次重试都递增。
- 相同编号、版本、标题和文本重复提交会直接返回 `unchanged:true`，不会重复建图。同版本不同内容或较旧版本会被拒绝。
- `owner` 只来自已认证服务端身份。HTTP请求体不接受调用者指定所有者。管理员也只能通过这些接口访问自己的资料。
- 当前权限粒度为个人私有库；共享团队库、管理员代管他人资料不在此接口范围内，不能通过传入 `userId` 绕过隔离。
- 当前每份文本最多12000个Java字符串长度单位，通常相当于12000个常见中文字符；标题最多200。长文件请先协商提高上限及异步任务方案，不要静默截断。
- 当前GraphRAG使用每1800字符分块、150字符重叠，片段编号是 `buildId:ordinal`。更新后构建编号和片段编号都会改变，旧向量不能继续召回。

## 三 现有HTTP接口

所有接口需要原系统登录返回的 `Authorization: Bearer <token>`。返回沿用 `{code:200,msg:"success",data:...}`；前端 `@/utils/request` 自动解包data。错误同时使用HTTP状态码和code：400参数或版本错误、401登录失效、403越权、503模块或依赖不可用。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/knowledge/status?probe=true` | 模块、模型配置状态和实际Neo4j连接检测，不返回密钥 |
| POST | `/api/knowledge/model-probe` | 实际请求一次已配置模型并检查OK回应，与“配置字段非空”区分 |
| GET | `/api/knowledge/documents` | 当前用户有效文件列表，不含已删除版本 |
| GET | `/api/knowledge/documents/{documentId}` | 当前用户文件文本、标题及当前版本 |
| POST | `/api/knowledge/documents` | 新建或更新解析后的文件文本，完成抽取和写图后发布 |
| DELETE | `/api/knowledge/documents/{documentId}?version=2` | 版本化删除，先移出检索，再清理Neo4j关系 |
| GET | `/api/knowledge/deletions` | 当前用户待物理清理的删除记录，刷新页面后仍可恢复 |
| GET | `/api/knowledge/graph` | 当前用户有效版本图谱，支持documentIds与entity查询参数，最多150条关系 |
| POST | `/api/knowledge/messages` | 按指定检索模式回答，并返回原文来源和关系 |

上传或更新请求：

```json
{
  "documentId": "sop-a100",
  "title": "A100生产工艺",
  "version": 1,
  "text": "A100鼠标需要点胶工序。点胶工序使用点胶机。"
}
```

新版本成功响应data示例：

```json
{"documentId":"sop-a100","version":1,"chunkCount":1,"relationCount":2,"unchanged":false}
```

`relationCount`由实际模型提取结果决定，示例数量不构成固定断言。相同版本重试只返回documentId、version、unchanged三个字段。抽取失败、Neo4j连接失败或写入失败时不会发布新版本；原有版本继续有效。新增文件失败时不能将其显示为“已成功建图”。当前为同步接口，最大8个文本片段逐一抽取，客户端建议600秒超时；超时后先按同版本重试或查询当前版本，不要直接覆盖原文件。

删除成功data：`{"deleted":true,"cleanupPending":false}`。若返回 `cleanupPending:true`，文件已退出检索，但物理图谱清理待重试。任务三将删除状态保存为DELETED_PENDING，`GET /deletions` 返回documentId、title、version；成功清理后改为DELETED。任务二也应保存自己的删除事件及版本，重试相同DELETE；重试不会清掉更高版本重新发布的关系。不要在第一次清理失败时将文件重新加入索引。

问答请求：

```json
{"question":"点胶工序涉及哪些设备和检验要求？","mode":"GRAPHRAG","documentIds":["sop-a100"]}
```

`mode`可选 `RAG`、`GRAPHRAG`、`HYBRID`。响应data包括：

- `answer`：文字答案，用 `[S1]` 等来源编号引用。
- `sources`：`id/documentId/title/version/chunkId/text`，真实参与回答的片段。
- `facts`：`source/relation/target/quote/chunkId`，图谱检索得到的关系。
- `retrieval`：真实检索实现描述。当前RAG默认是明确标注的关键词基线，不能在报告中称为向量检索。
- `model`：实际配置的模型名；没有相关依据时返回资料不足，不调用模型。

`documentIds`为可选数组，缺省或空数组表示本用户全部有效资料，最多50份。任一编号不存在、已删除或不属于本用户时整体拒绝，不会退回全库检索。原有仅含question、mode的请求继续可用。图谱接口使用同名重复查询参数，如 `?documentIds=sop-a100&documentIds=equipment&entity=点胶机`，entity用于从整个授权图中检索该实体附近的两跳关系；不传entity时展示范围内关系。前端本地搜索只过滤当前可见子图，不能替代数据库实体查询。

task3-r3的status额外返回revision、vectorRetrieverConnected、supportedModes及maxDocumentCharacters，可用于确认部署版本和向量扩展是否替换默认基线。直接实体匹配失败后的候选实体定位仍严格限定用户与资料范围。问答生成期间若文件改变，接口会拒绝返回旧版本答案，请提示用户刷新并重试。合法的“当前资料不足，无法回答该问题。”属于无业务结论的固定拒答，不要求正文引用编号；已有来源仍保留在sources中供核对。

## 四 向量检索扩展接口

优先采用同一Spring Boot进程中的Java接口。实现 `com.mouse.mes.knowledge.RagRetriever` 并注册为一个Spring Bean；默认关键词实现通过 `@ConditionalOnMissingBean` 让位。建议在 `knowledge/rag/` 新包开发，避免改写任务三服务。

```java
public interface RagRetriever {
    String name();
    List<KnowledgeTypes.Chunk> retrieve(
        long owner,
        String question,
        List<KnowledgeTypes.Chunk> authorizedChunks,
        int limit
    );
}
```

`authorizedChunks` 已由任务三从当前用户、当前有效版本过滤。召回必须同时过滤owner、documentId、version和chunkId；返回列表必须取自传入的这些Chunk对象，最多limit条。不要重新构造不同内容或用旧片段编号冒充当前版本；服务层会拒绝未授权或被改写的片段。`name()` 返回真实实现名，例如“向量检索 · 模型名”，便于答辩展示。

当前没有单独的向量同步事件总线。为先完成接入，可在 `retrieve` 中对比传入Chunk的编号与本用户索引，批量补充新片段并删除失效片段，再召回；后续再一起增加可靠的提交后事件。索引刷新失败应明确报错，不得返回上一个用户的缓存。不要在所有者校验之前查询无过滤的全库TopK，再从结果中猜测权限。

如果任务二使用Python服务，也保留Java `RagRetriever` 适配器，由它在服务端调用Python检索接口，校验返回的片段编号后映射为传入Chunk。Python服务的地址和认证信息仅配置在后端，前端不能直接传owner冒充其他人。

## 五 文件库到图谱的可靠同步

同进程时，文件库业务层在完成身份校验和文本解析后调用 `KnowledgeService.upsert(owner,input)`。必须通过Spring注入的服务代理调用，使事务生效。文件管理操作需要保留同步事件：owner、documentId、version、动作、文本或文本存储位置、处理状态和失败次数。

建议原始文件状态分为“已上传／索引中／可检索／失败待重试”。上传成功不等于两种索引均完成。文件更新先保留旧可检索版本，待图谱和向量两侧均成功后展示最新同步状态；当前模块独立发布图谱版本，不自动协调任务二的向量事务。

删除时先提交文件库的权限撤销和任务三 `tombstone`，让两侧立即停止检索；然后清理向量和Neo4j。任务三HTTP删除接口已实现自己的tombstone提交后清理；同进程调用时需在外层事务提交后再调用 `cleanup(owner,id,version)`。不要把外层事务包住网络清理后就假设已经完成跨库原子提交。

当前图存储保留旧构建关系，但查询只允许MySQL中已发布的buildId。进程在写图后、发布前中断时可能留下不可检索的孤立构建；文件删除会清理不高于删除版本的关系。尚未提供定时孤立构建回收。这种发布策略防止半成品图谱变成可见结果，不等同于MySQL与Neo4j分布式事务。

## 六 合并和联调清单

任务三分支名为 `feature/task3-graphrag`。任务二建议使用 `feature/task2-rag`，任务一使用独立登录分支。双方共用入口、登录状态和返回格式；业务包分开开发。

1. 用户A上传A100资料；A能查看文件和图谱，用户B不能读取A的文件编号，也不能通过问答获取A的内容。
2. 同一个文件同版本重试不增加关系；同版本改内容被拒绝；更高版本发布后问答只返回新版本来源。
3. 文件库支持至少老师要求的多种格式，下载内容与原文件一致；解析错误应可见。
4. 接入向量Bean后RAG模式返回真实向量召回，GraphRAG模式使用两跳图谱，HYBRID同时包含两类证据。
5. 用原文包含的实体名进行跨文件两跳提问，例如“点胶工序使用的设备由谁负责？”，核对工艺资料和点检资料的来源。
6. 删除文件后图谱、向量检索和问答都失效；模拟Neo4j离线，确认清理待重试但文件不重新可见。
7. 更换登录用户、过期Token、伪造请求体userId、旧版本事件均不能绕过隔离。
8. 刷新页面后仍能读取待清理删除记录；仅重试本用户记录，不能通过待清理列表读取其他用户标题。

需要共同协调的文件为 `router/index.ts`、`Sidebar.vue`、`stores/auth.ts`、`RolePermissions.java` 和 `application.yml`。冲突时按功能合并，避免整份覆盖。任务一应沿用现有 `userInfo.id` 和会话校验，避免人脸登录产生另一套身份。
