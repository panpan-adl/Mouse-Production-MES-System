# MouseMES 火山方舟模型接入说明

任务三使用火山引擎火山方舟，基础地址为 `https://ark.cn-beijing.volces.com/api/v3`，模型ID为 `doubao-seed-2-1-lite-260915`。后端自动追加 `/chat/completions`。本机已完成密钥配置及真实导入问答联调，见[真实联调记录](火山方舟真实联调记录.md)。在新窗口或新机器启动时仍需重新配置密钥。

## 配置与启动

本机也可以直接双击项目根目录的 `启动知识图谱.cmd`。它会打开PowerShell，提示输入模型密钥，自动复用本机Neo4j配置，并构建重启后端；过程显示四个阶段。密钥只保存在该窗口及它启动的后端进程内。关闭窗口后若需再次重启，可重新双击并输入密钥，无需重复粘贴多条命令。

在项目根目录打开PowerShell，执行：

```powershell
. ./08-environment/Use-Knowledge-Ark.ps1
```

脚本会以隐藏输入方式询问API密钥，仅写入当前PowerShell进程的环境变量，不保存到文件、不打印密钥。若当前会话已有 `MES_KNOWLEDGE_MODEL_API_KEY` 或 `ARK_API_KEY`，脚本直接复用。配置的非敏感项是：

```text
MES_KNOWLEDGE_ENABLED=true
MES_KNOWLEDGE_MODEL_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
MES_KNOWLEDGE_MODEL=doubao-seed-2-1-lite-260915
```

随后在同一个窗口配置Neo4j连接并启动项目。普通Neo4j实例参见[任务三部署与验收说明](任务三部署与验收说明.md)。本机前轮下载的独立测试实例HTTP端口为17474，不能与默认7474混淆；测试实例当前已停止。

```powershell
# Neo4j必须已启动，以下URL按实际实例修改
$env:MES_KNOWLEDGE_NEO4J_URL = 'http://127.0.0.1:7474'
# 设置该实例对应的MES_KNOWLEDGE_NEO4J_PASSWORD后，在同一窗口启动
./08-environment/Start-MouseMES.ps1
```

已启动的旧后端不会自动读取新环境变量，需要正常停止后再启动；首次运行使用重新构建的后端包。仅重复点击网页刷新不能替代后端重启。

## 联调顺序

1. 在火山方舟控制台确认所用API密钥具备该模型的调用权限。
2. 登录MouseMES，进入“智能与提醒 → 私有知识图谱”。
3. 点击“测试模型”，检查是否显示“已实测连接”。这会发送一次最多32输出token的简短请求，不上传私有文件。
4. 点击“检测连接”，确认Neo4j可连接。
5. 导入演示资料，观察模型提取的真实实体和关系；再导入第二份资料，测试跨文件两跳问题。
6. 展开回答来源，核对引用和资料版本。记录实际耗时、抽取结果和答案质量后再写课程验收结论。

## 已适配的请求行为

火山方舟豆包Seed模型请求显式设置 `thinking.type=disabled`、`stream=false`。抽取请求额外设置 `response_format.type=json_object`，输出仍通过原文实体、连续引用和结构校验。普通回答使用自然语言和来源编号，不要求JSON。通用本地或其他服务商接口不会自动携带这些方舟专用参数。

HTTP401提示检查密钥，403提示检查调用权限与服务开通，404提示检查模型ID或基础地址，429提示检查额度或频率。服务商原始错误体不会直接展示，避免错误回显夹带请求内容。真实请求时如仍有兼容性问题，以控制台调用示例和实际状态为依据调整，不把失败替换为模拟成功。

官方参考：[Chat接口](https://docs.volcengine.com/docs/ark/chat-api)、[深度思考开关](https://docs.volcengine.com/docs/ark/deep-thinking)。模型默认思考行为与可选值以服务商文档为准。
