## 3. 用户身份与私有库

复用原系统的 `Authorization: Bearer <token>`，由现有TokenInterceptor校验会话，owner只取服务端 `userInfo.id`。

当前为个人私有库，不提供管理员读取他人文件的例外。前端不指定owner或userId。查询参数出现owner/userId会拒绝；问答JSON只允许question和mode字段。文件详情、下载、重试、更新、删除及同步payload都再次按owner过滤。

以下是本机浏览器实测留下的一条虚构演示文件记录，owner由已登录用户取得，不能照此从客户端传入：

```json
{
  "owner": 1,
  "documentId": "43aecb5d-fcd1-469b-8195-548a62997f1f",
  "filename": "A100工艺演示.txt",
  "title": "A100工艺演示（虚构）",
  "version": 1,
  "activeVersion": 1,
  "status": "READY"
}
```

文件ID稳定，1至64位ASCII字母、数字、短横线或下划线；创建、更新、删除版本依次递增。version记录最新操作，activeVersion记录实际可检索版本。失败更新可能出现version=2、activeVersion=1。

## 4. 当前文件接口

任务二暂使用 `/api/rag` 命名空间，避免抢占你们已有的 `/api/knowledge` 控制器。所有请求都需要原Token。

统一成功包装：`{"code":200,"msg":"success","data":...}`。错误使用HTTP 400/403/503及同值code；401由现有登录拦截器处理。不能读取他人文件时，统一提示“文件不存在或无权访问”。

| 方法与路径 | 参数 / data |
| --- | --- |
| `GET /api/rag/status` | 模型配置状态、准确模型ID、维度、向量存储描述；不返回密钥 |
| `GET /api/rag/documents` | 当前用户未删除文件列表，字段documentId/version/activeVersion/title/filename/status/error/attempts/createdAt |
| `GET /api/rag/documents/{id}` | 当前版本的标题、正文text、状态、activeVersion等；不泄露磁盘路径 |
| `POST /api/rag/documents` | multipart：documentId、version、title、file；创建和更新共用 |
| `GET /api/rag/documents/{id}/download` | 原始二进制附件；不改写原件。更新失败时默认下载旧可检索版本；无旧版时下载当前原件 |
| `POST /api/rag/documents/{id}/retry?version=2` | 重试原失败版本，不重新递增；已完成重试返回unchanged:true |
| `DELETE /api/rag/documents/{id}?version=2` | 版本化删除；返回deleted、cleanupPending、graphCleanupPending及version |
| `GET /api/rag/events` | 当前用户最近100条持久化处理事件，包括已删除文件 |
| `GET /api/rag/documents/{id}/sync-payload` | 当前可检索版本的documentId/title/version/text，正好可供你们upsert使用 |
| `GET /api/rag/events/{id}/{version}/sync-payload` | 当前事件：UPSERT返回action和payload；DELETE返回action/documentId/version。旧事件会拒绝 |
| `POST /api/rag/messages` | JSON：question、mode；目前只接受RAG，其他模式明确返回未合并提示 |

上传示例，不附真实密钥：

```bash
curl -X POST http://127.0.0.1:8086/api/rag/documents \
  -H "Authorization: Bearer <登录Token>" \
  -F "documentId=sop-a100" -F "version=1" \
  -F "title=A100生产工艺" -F "file=@A100工艺演示.txt"
```

成功索引data示例：

```json
{"documentId":"sop-a100","version":1,"status":"READY","chunkCount":1,"graphStatus":"PENDING_TASK3","unchanged":false}
```

失败索引data示例，HTTP成功只表示原件保存及事件记录完成，不能把FAILED当成索引成功：

```json
{"documentId":"sop-a100","version":2,"status":"FAILED","error":"模型接口HTTP 403，请检查模型开通、API权限和余额；未生成答案或发布索引","graphStatus":"PENDING_TASK3"}
```

multipart重复上传同一版本会返回400，不等同于你们文本同步接口的幂等upsert。超时后先查列表/详情，使用retry重试已保存的同一版本，不能直接递增版本。客户端上传等待时间为600秒。

## 5. 文本解析与分块

- 支持PDF、DOCX、UTF-8 TXT、Markdown、CSV；最大2MB，提取正文最多12000个Java UTF-16长度单位。
- PDF逐页提取，来源位置如“第2页”；最多100页。扫描PDF没有文字时明确提示需要OCR；尚不支持OCR、图片文字识别和旧版DOC。
- DOCX用安全XML解析提取正文段落，包括正文中的表格文本，保留“段落N”；禁用DTD和外部实体，不解压任意磁盘路径。
- TXT/MD/CSV严格按UTF-8读取，损坏编码报错。CSV作为文本资料，不额外解释为业务数据库数据。
- 超过上限或解析失败会记录FAILED和错误，不静默截断，也不会发出成功索引信号。
- 原件保存在随机内部文件名下，客户端文件名不作为磁盘路径，下载仍给出原文件名。
- 正文可通过详情接口的text获取；完成向量化后可通过sync-payload获取可发布给图谱的正文。更新失败时详情可能是失败新版，图谱同步必须使用sync-payload而不是直接用详情text。
- 同意每1800字符分块，重叠150，即步长1650；最多8块。与任务三均采用Java字符串下标。

重要：双方合并时必须让你们发布的 `buildId:ordinal` 成为RAG/GraphRAG共享来源编号。任务二独立页面目前使用自己的buildId，不能把这些编号冒充你们的图谱片段。下面的授权片段索引就是为接收你们的真实Chunk对象准备的。

## 6. 向量方案与Java接入

真实嵌入模型：`doubao-embedding-vision-251215`，纯文本调用 `/embeddings/multimodal`，固定1024维float稠密向量。对话模型：`doubao-seed-2-1-lite-260915`。

已用本人提供的火山方舟密钥完成真实调用，不使用他人凭证。旧的 `doubao-embedding-large-text-250515` 在该账号返回404，所以未继续采用。

向量存储为本机MySQL表 `rag_vector`，向量字段JSON，按owner、稳定文件ID和activeVersion过滤后计算余弦并取TopK；属于小型私有库的精确向量检索，没有ANN/HNSW索引。无需额外启动Qdrant或Python。当前实现适合课程数据量，数据很大时应另行迁移到专用向量库。

相关实现：

- `RagParser`：解析与分块。
- `RagFileService`：原件、版本、发布、删除及事件。
- `RagModelClient`：真实模型调用、1024维校验、用量预约、输出引用校验。
- `RagVectorService`：本机文件库的向量RAG问答。
- `AuthorizedChunkIndex`：给任务三RagRetriever的同进程向量桥接核心，使用独立表 `rag_authorized_vector`，不混淆双方buildId。

桥接方法签名：

```java
public <T> List<T> retrieve(
    long owner, String question, List<T> authorizedChunks, int limit,
    Function<T, RagTypes.Chunk> mapper
) throws Exception;
```

你们的 `RagRetriever.retrieve(owner,question,authorizedChunks,limit)` 实现中调用上面方法即可。mapper把真实KnowledgeTypes.Chunk的字段映射成：

```java
new RagTypes.Chunk(chunkId, documentId, version, title, text, location)
```

这里的chunkId必须使用你们的 `buildId:ordinal`，不能新造UUID。`name()`可直接返回 `AuthorizedChunkIndex.name()`。

该方法先对比本owner授权集合和指纹，删除失效片段、补嵌入新片段，然后只在传入的授权对象集合中做余弦TopK，返回的就是传入对象本身。owner、documentId、version、chunkId、title和text都参与隔离/内容指纹。失败直接报错，不退回旧缓存或关键词结果。

当前没有复制你们尚未收到的 `KnowledgeTypes`、`RagRetriever` 或 `KnowledgeService`，也未注册一个假接口Bean。需要拿到源码后，按实际Chunk字段补上很薄的一层 `implements RagRetriever` Spring Bean；你们的关键词基线再按ConditionalOnMissingBean让位。已测试桥接核心返回原对象、更新清旧片段、空授权集合清库和跨用户隔离，但尚未测试你们实际接口Bean装配。

## 8. 更新、删除与共同决策

**决定一：** 任务二保存原始文件和解析正文，documentId作为双方唯一逻辑文件编号，owner均取现有会话；任务三只接收解析文本及定位信息，不另造用户。

**决定二：** 任务二 `rag_revision` 持久化owner/documentId/version/action/解析文本/状态/错误/失败次数/原件路径。上传同步解析、生成向量，MySQL事务一次发布；失败保留原activeVersion。重试同一事件版本，不递增。删除先提交tombstone和向量移除，再清原件；清理失败有CLEANUP_PENDING和重试入口。

图谱双写目前还没接上，graphStatus明确PENDING_TASK3，graphCleanupPending也不会谎报完成。建议收到源码后新增单独graph同步状态，并由任务二业务服务注入你们的Spring代理：upsert调用 `KnowledgeService.upsert(owner,input)`；删除外层tombstone提交后再调用你们的cleanup。若需通过HTTP调用，使用当前用户Token，不前端直传owner。双方应共同实现可靠提交后事件重试及发布协调，不把向量完成等同于图谱完成。

**决定三：** 合并后由任务三提供当前owner、当前已发布buildId的authorizedChunks，任务二桥接索引只对这组真实对象向量化并召回；保持原对象返回，由你们服务继续校验。图谱离线或重建失败时，不能让未发布新版本进入RAG/GraphRAG混合结果。
