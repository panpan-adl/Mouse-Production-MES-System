## 人脸阶段

已验证未登录和错误密码无法录入或解绑、挑战一次性消费、正常亮度无脸画面和暗画面被拒绝。已验证失败保留摄像头、手动关闭，以及模拟保存成功后的弹窗与关镜头。SFace 与 MiniFASNet 分别完成了模型推理。

独立验收库已确认保存一条真人录入模板。只核对模型版本和字段长度，随机数 12 字节、密文 528 字节。浏览器使用模拟识别响应验证了光圈、姓名和工号确认弹窗及岗位跳转。

在独立测试实例上，已验证本人绑定状态接口，以及推理地址不可达时人脸登录返回业务码 503、拒绝签发会话、密码登录仍可用。20 次并发无效采集全部被拒绝，同时 5 次密码登录成功。无效采集测试未执行人脸推理。

推理并发复测：使用真实 OpenCV 检测器和正常亮度的合成无脸画面。调整前，经本机 HTTP 以 12 路并发发送 60 次请求，1 次进入检测并拒绝无脸画面，59 次返回忙碌（HTTP 503）。调整后，使用 Flask 测试客户端对同一推理入口以 4 路并发发送 12 次请求，全部进入检测并正确拒绝，最长 111 ms。故意占用推理锁时，约 1.015 秒后返回 HTTP 503，释放后下一请求正常进入检测。两轮的客户端和并发数不同，结果不作为吞吐量对比，也不代表真人刷脸延迟。

调整后另按相同本机 HTTP 条件复测（12 并发、60 请求），60 次均进入检测并拒绝无脸画面，0 次忙碌，吞吐量 22.12 请求/秒，客户端 p50 / p95 / p99 为 337.4 / 1295.9 / 1380.8 ms。此轮覆盖 HTTP 排队和无脸检测，未执行真人活体及特征提取。

完整链路复测：通过 5177 前端代理、Java 后端和 Python 推理服务，以 12 路并发执行 60 次挑战及无脸登录循环。60 次均明确提示未检测到清晰人脸，无会话签发或服务忙碌，压测后下一请求仍正常进入检测。完整循环吞吐量 17.8 次/秒，登录请求 p50 / p95 / p99 为 566.0 / 623.8 / 629.7 ms。

2026-11-12，用户实际运行的 localhost:5173 已接通人脸服务。只读核对 mouse_mes_restore，已有 2 条人脸模板和 4 条人脸登录成功审计记录。免工号接口不接收工号。审计记录证明服务已成功签发会话，未记录浏览器是否进入对应工作台，也无法据此判断这 4 次是否使用了最新的多人判定。

5173 新版复测：6 路并发的 24 次无脸登录和 24 次重复挑战均被拒绝。无脸登录 p50 / p95 / 最长为 112.2 / 163.6 / 170.2 ms。使用同一合成裁切图运行实际 SFace，旧提取路径和新版复用路径的特征最大差值为 0。Edge 使用模拟识别响应验证新版弹窗显示工号及进入工作台后账号一致。
