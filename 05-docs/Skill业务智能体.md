# MouseMES Skill 业务智能体

入口为左侧“Skill业务智能体”，也可以点击各业务页面右下角的“业务智能体”。地址为 `/assistant`。这是嵌入 MouseMES 的业务助手，不是安装到 Codex 的开发技能。

## 可以完成什么

| 技能 | 实际行为 | 示例 |
| --- | --- | --- |
| 库存查询 | 调用已有参数化业务查询，展示条件、时间、余额与来源流水 | 查询当前原材料库存 |
| 缺料分析 | 结合未领料需求、安全库存与可用量，逐物料列出缺口 | 分析当前缺料和安全库存 |
| 工单追溯 | 查询完整工单、订单或计划编号的关联记录；缺少条件时追问 | 追溯 MO-000001（请换成真实编号） |
| 点检保养待办 | 查询已生成、截至今天到期且未完成的周期任务 | 检查到期的点检保养任务 |
| 补货建议确认 | 读取安全库存补货建议，选择物料生成确认任务，点击确认后登记建议 | 帮我处理需要补货的物料 |

技能按当前用户岗位授权。仓储等岗位可以查看补货建议，只有采购负责人和管理员可生成、确认写入任务。确认补货建议不等于创建采购订单，也不会修改库存。补货建议采用安全库存口径，缺料分析还考虑未领料需求，二者数量可能不同。

确认任务有效期10分钟。确认时重新读取库存；数量改变、已被其他任务确认或已无补货需求时，要求重新核对。重复确认同一成功任务返回原结果，不重复执行。任务归属用户，确认操作写入业务审计；岗位变更后不再开放原岗位的技能结果。

## 对话和任务记录

一次处理一个技能任务，可选择技能或自动识别。库存等查询支持补充条件；更换技能时不沿用另一种查询的条件。任务记录保存在 `mm_agent_run`，查询技能同时沿用原有查询审计。最近30项任务可从侧栏重新打开。历史结果是当时快照，需要最新数据时重新发送查询。

目前不支持任意业务自动化、自动采购下单、库存修改、自动完成保养或自动发货。模型只负责选择已授权技能、解析查询条件，业务执行由服务端已有业务服务完成；不会执行模型生成的 SQL、脚本或 URL。数据来源中的文字只作为数据展示。

## 大模型接入

默认 `MES_AI_MODE=local`：本地规则选择技能和查询条件，页面明确标记未调用大模型。没有填入或测试任何真实 API Key。

远程模式复用现有服务端变量：

| 变量 | 内容 |
| --- | --- |
| MES_AI_MODE | remote |
| MES_AI_BASE_URL | 模型服务的接口根地址，例如 `https://api.deepseek.com`；不包含 `/chat/completions` |
| MES_AI_MODEL | 账户实际可用的模型名称 |
| MES_AI_API_KEY | 服务端环境变量中的密钥，不放入前端或提交 Git |

使用 JSON 格式的 Chat Completions 接口。适配依据：[DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。DeepSeek 官方地址下关闭思考模式以适应技能路由的短输出限制；其他兼容服务不发送此专属参数。接口失败、超时、返回截断或非白名单技能时，明确报错，不伪造结果。

远程自动识别会将任务文字和已授权技能说明发送给配置的模型服务；库存类条件解析还会发送当前问题和已有筛选条件，业务结果由本地数据库查询，不发送给模型生成结论。每个用户每天共享原有20次模型调用预算；自动路由加查询解析可能使用2次，单次路由上限256 Token、查询解析512 Token。

密钥设置到当前 PowerShell 环境后，可使用 `08-environment/Restart-Agent-Demo.ps1 -Mode remote -BaseUrl <接口根地址> -Model <模型名称>` 重启隔离演示后端。脚本检查原进程归属；不会停止不属于项目记录的进程。默认不传参则以本地模式启动。该脚本使用现有 MySQL、Redis，启动前需确认两者正在运行；不重建数据库。

实际模型连接和效果需要在用户提供接口配置后再验收。现阶段用本地 HTTP 模拟服务验证请求协议与未授权技能拦截，不能据此宣称已连通 DeepSeek。

## 扩展技能

元数据位于 `01-backend/src/main/resources/agent/skills.json`，包含技能标识、描述、例句、岗位与是否写入。新增条目还需在 `SkillAgentService` 添加确定的服务端执行分支及相应测试；仅改 JSON 不会获得任意执行权限。
